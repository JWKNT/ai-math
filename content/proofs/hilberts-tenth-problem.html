The proof has the same overall shape as the 1970 proof for whole numbers. It shows that a method for fractions would give a method for whole numbers, and no such method exists. The new work is the link between the two. For each equation \(f\) with whole numbers in it, the paper builds a long list of tests. Each test asks finitely many questions of the form "does this equation have a fraction solution".

The list is built so that \(f\) has a whole-number solution exactly when every test passes. Suppose a method for fractions existed. Then two searches could run side by side. One search tries whole numbers in \(f\), and it stops if it finds a solution. The other runs the tests one by one, and it stops if a test fails. One of the two searches must stop, so together they decide \(f\), which the 1970 result rules out.

The tests store whole numbers on an elliptic curve, a curve of the form \(y^2 = x^3 + ax + b\). Points on such a curve can be added by a formula with fractions. Adding a point \(P\) to itself \(n\) times gives a point \(nP\) that stores \(n\). Addition of stored numbers is then easy. Multiplication is not, because the curve has no direct formula for it. So the tests also compare each fraction with its stored number at many primes, and they force the two to agree there.

The deepest input is a height estimate. The height of a fraction measures the size of its top and bottom. The estimate says that a fraction cannot have a large height unless it comes close, at many primes, to one of five fixed points. The tests control those primes. So every number that the tests allow has a height at most a fixed multiple of the size \(B\) of the stored numbers.

Points on a curve grow faster than that. Take the point \((3, 5)\) on \(y^2 = x^3 - 2\). For \(n\) from 1 to 6, the top of the first coordinate of \(nP\) has 1, 3, 6, 10, 15 and 21 digits. The digits grow roughly like the square of \(n\). So the height of \(nP\) grows like \(n^2\), while the tests keep it near \(B\). This forces every stored number to be small, so the stored numbers are ordinary whole numbers that solve \(f\).

One step of logic holds this together. If every finite group of tests can pass, a tool called compactness gives a larger number system in which all the tests pass at once. The argument above runs inside that system and finds a whole-number solution of \(f\). So if \(f\) has no whole-number solution, some test must fail, as the plan needs. OpenAI reports this proof.
